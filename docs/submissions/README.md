# 公開用ドラフト（コピペで投稿できる形）

このフォルダは、既存の技術記事 `../catching-api-contract-drift-in-ci.md` を
**各プラットフォームの投稿フォーマットに変換した完成ドラフト**です。
社長（またはYuki）は、内容を確認して各サービスに貼り付けて公開するだけでOKです。

公開は外部アカウントのログインが必要なため、こちらでは投稿できません。
アカウントをお持ちのプラットフォームを1つ選んでいただければ十分です。

## ファイル一覧

| ファイル | プラットフォーム | 言語 | 使い方 |
|---------|-----------------|------|--------|
| `zenn-ja.md` | [Zenn](https://zenn.dev/new) | 日本語 | 新規記事作成→中身を全コピペ。`published: true` にして公開 |
| `qiita-ja.md` | [Qiita](https://qiita.com/drafts/new) | 日本語 | 新規投稿→中身を全コピペ→公開 |
| `devto-en.md` | [dev.to](https://dev.to/new) | 英語 | "Write a post"→本文にコピペ（frontmatterは反映されます）|

いずれも冒頭に frontmatter（タイトル・タグ等）が入っています。
**Qiita/Zenn は `published: false`（下書き）にしてあります** → 内容確認後に true へ。

## 公開の効果

- 記事は既に自分のリポジトリで公開済み（canonical URL 明記済み）。
  重複コンテンツのペナルティは canonical で回避。
- 記事末尾から GitHub リポジトリ → Gumroad 商品ページへ導線あり。
- 想定流入: dev.to/Qiita/Zenn の技術記事経由で "api contract testing" 等の
  検索流入。GitHub 単体では views=0 だった層へのリーチがここで初めて発生。

## 注意（誠実性）

- 記事は実測ベース（2026-11-09 実行ログ）で誇張なし。
- 「有料」は商用ライセンスの話で、コード自体は MIT。事実のみ記載。

## 公開後にやること（私の担当）

- 記事の URL を共有いただければ、README と Gumroad 説明文に逆リンクを追加。
- アクセス数を見て、反応の良いプラットフォームに追加記事を出す。
